# Final demo checklist

Use this before a live review or interview:

- [ ] backend is running locally
- [ ] frontend is running locally
- [ ] dashboard loads without errors
- [ ] merchant risk view is visible
- [ ] active incidents are visible
- [ ] investigation panel opens for a selected incident
- [ ] evidence-backed explanation is readable
- [ ] verification status is visible
- [ ] local anomaly signal is labeled honestly as supplemental
- [ ] analyst action flow is visible
- [ ] audit trail is populated
- [ ] evaluation summary is visible
- [ ] synthetic data boundaries are clearly communicated
- [ ] Razorpay / external payment integration is clearly described as demo/test-only if present
- [ ] no secrets or live credentials are exposed
- [ ] README is polished and consistent with the live product
- [ ] architecture and limitations docs are aligned with the implementation
- [ ] demo script is ready to present without overclaiming

## Final confidence check

The product is ready for a demo when the reviewer can see a clear story:

fraud signal → incident → evidence → investigation → human decision → audit

and when the project is honest about its boundaries.
